# 全产线政策情报站设计

## 1. 目标与边界

新建一个独立的“全产线政策情报站”，面向领导和客户经理汇集五条产线的政策信息与业务研判：AI、大数据、安全、视联网、智能运维。

现有“北京 AI 政策情报”站继续作为 AI／大数据的专题站，保持原有网址、内容和导航，不与新站混合。新站先发布为私有 Sites 版本供确认；只有用户明确确认后才同步到 GitHub Pages。

政策事实只使用可回溯的官方原文或官方附件。新闻、公众号、行业媒体仅作为检索线索，未取得官方依据时进入“待核实”，不得作为正式政策或补贴事实展示。

## 2. 信息架构

新站采用“一个入口、五条产线、同一套政策层级”的架构：

```text
首页总览
├── 全产线政策分析
├── 本周最新
├── 补贴与申报机会
├── AI
├── 大数据
├── 安全
├── 视联网
└── 智能运维

每条产线页面
├── 整体政策态势
├── 政策分析、趋势与预警
├── 国家政策
├── 北京市级政策
├── 区级政策
├── 补贴／申报与项目机会
└── 客户分类与行动提示
```

首页横向比较五条产线的政策数量、重点动态、活跃申报、合规关注与待核实事项。进入某条产线后，默认先显示该产线的整体态势和高优先级政策，再按国家、北京市级、区级筛选。

## 3. 产线口径

| 产线 | 覆盖口径 | 重点客户与机会 |
| --- | --- | --- |
| AI | 人工智能、大模型、智能体、算力、行业模型与 AI 场景 | 模型与智能体企业、算力与云服务商、行业客户 |
| 大数据 | 数据基础设施、公共数据授权运营、数据要素、数据产品、可信数据空间、数据治理 | 数据运营机构、数据服务商、公共数据运营与行业客户 |
| 安全 | 网络安全、数据安全、关键信息基础设施保护、密码应用、安全服务与安全产品 | 安全厂商、政企客户、集成商与运营服务商 |
| 视联网 | 视频专网、视频汇聚与治理、视联网、视频 AI、城市治理和行业视频应用 | 政务／园区／城市治理客户、视频平台和网络集成商 |
| 智能运维 | 泛行业 IT 运维平台、AIOps、云网集成、信创集成、网络规划、机房运维、设备维保、综合布线、驻场运维 | 云网与系统集成商、信创生态厂商、数据中心和政企 IT 运维客户 |

政策可同时关联多条产线。例如，可信数据空间可归入“大数据”和“安全”；视频 AI 场景可归入“视联网”和“AI”；数据中心智能化可归入“智能运维”和“安全”。页面以主产线呈现，相关产线同时保留关联标签，避免重复建档。

## 4. 政策记录与分析规则

每条政策以稳定 `policyId` 管理，记录正式标题、发文机关、层级、地区、发布日期、生效／失效状态、所属产线、主题、官方来源和核验日期。一个政策可关联多个项目申报批次；申报批次包含状态、截止日、入口、对象、支持方向、金额或比例和材料要点。

每条正式政策固定展示四类内容：

1. 政策概要：官方事实的简短提炼。
2. 企业机会：可服务的客户、场景、产品或集成机会。
3. 合规与交付影响：资质、数据安全、网络安全、信创、验收、运维边界等约束。
4. 行动提示：客户经理可执行的核验、材料准备、场景沟通或持续跟踪动作。

“全产线政策分析”只汇总已核验政策形成的趋势、依据链和预警，并明显区分“已核验事实”和“业务研判”。各产线的客户分类按目标客户、常见需求、可切入政策、关键提问和下一步动作组织。

## 5. 数据与核验流程

首批建设以国家、北京市级和北京重点区为范围。优先扫描中国政府网、国家网信办、工信部、国家数据局、北京市经信局、北京市政务服务和数据管理局、北京市网信办、首都之窗，以及重点区政府和政策兑现栏目。

新增主题使用以下检索线索后回到官方原文核验：

- 安全：网络安全、数据安全、关键信息基础设施、密码应用、安全服务。
- 视联网：视联网、视频专网、视频汇聚、视频治理、视频 AI、城市运行。
- 智能运维：AIOps、IT 运维、云网、信创、数据中心、机房、网络、设备维保、综合布线、驻场服务。
- 大数据：可信数据空间、公共数据授权运营、数据基础设施、数据流通、数据产品、数据要素。

每次更新必须区分新增、修订、申报开启、截止临近、失效和待核实。没有正式依据的政策线索不进入正式分类库；已截止事项从“可申报”入口移出，但在当周变化中保留原因和日期。

## 6. 页面与交互

- 首页：五条产线的全景指标、重点变化、近期申报和领导判断。
- 产线页：顶部产线说明与重点判断，下面提供“全部／国家／北京市级／区级”筛选及政策卡片。
- 政策分析页：按产线的趋势卡、政策依据链、合规预警、客户准备度和管理建议。
- 本周最新：所有产线的已核验变化，带产线标签和调整类型。
- 补贴与申报机会：只显示已核验且仍有效或可准备的项目，并提供主产线、适用条件、支持方向、金额、期限、入口与政策依据。
- 客户分类：按五条产线分别形成客户机会地图与行动提示。

沿用现有站点的信息层级、低干扰配色与“先行动、再阅读依据”的阅读顺序；不新增面向访客的来源库页面。完整扫描网址与证据索引只在后台源数据中保存。

## 7. 验收标准

1. 五条产线均有独立入口，且每条均能查看整体、国家、市级、区级、分析和客户行动内容。
2. AI 与大数据可以复用现有已核验记录；安全、视联网、智能运维的首批记录均有官方来源或清晰的待核实标识。
3. 每条正式政策都有来源、日期、状态、产线、概要、企业机会、合规／交付影响和行动提示。
4. 申报页面不将已截止、无入口或仅有媒体线索的事项显示为“当前可申报”。
5. 政策关联、统计指标、导航和页面渲染均有自动化校验。
6. 首先部署到既有私有 Sites 环境；用户确认后再生成 GitHub 同步提交并发布公网版本。

## 8. 非目标

- 不把新闻、公众号内容直接写成正式政策结论。
- 不承诺所有区均有同等数量或同等精度的政策；未扫描或未核验区域必须明确显示状态。
- 不在首期引入客户 CRM、线索分配、登录权限或在线申报代办能力。
