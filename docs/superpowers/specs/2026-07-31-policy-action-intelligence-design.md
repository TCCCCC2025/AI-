# 北京 AI 政策情报：行动情报升级设计

## 目标

在现有“首页总览 + 本周最新 + 国家 / 北京市级 / 区级政策库”基础上，将政策展示升级为面向领导研判和业务拓展的行动情报。

本次交付聚焦四项能力：

1. 每项政策给出结构化解读和明确的机会 / 合规判断。
2. 展示政策之间的上位依据、配套细则和同主题关联。
3. 标注可能涉及的客户类型、业务场景和建议动作。
4. 管理政策生命周期，避免失效或待核内容被误当作有效结论。

## 方案选择

### 方案 A：在现有政策卡片中扩展（采用）

政策列表仍使用当前分类页面；卡片首屏展示判断结论，详细分析采用分区呈现。首页增加机会与风险看板。

优点是改动集中、上线快、每周维护成本低，用户不需要在列表页和详情页之间频繁跳转。现有 36 项政策可渐进补齐分析，不阻塞本次升级。

### 方案 B：为每项政策建立独立详情页

适合后续沉淀证据摘录、申报批次、客户线索和历史版本，但首期会产生大量内容页，维护成本较高。

### 方案 C：新增独立客户商机页

适合销售团队按行业或客户类型查找政策，但当前数据量较小，容易与三个政策分类页重复。待客户标签积累稳定后再建设。

因此本期采用方案 A，同时在数据模型中预留独立详情页和客户商机页所需字段。

## 信息架构

### 首页

保留现有政策全景，在其下新增两个区域：

- “本期判断”：展示机会政策数、合规关注数、待回核数和正在滚动核验的事项数。
- “机会与风险看板”：列出最值得跟进的政策机会、主要客户类型和近期合规提醒。

首页只展示聚合结论和重点政策，不完整重复分类政策库。

### 国家、北京市级、区级页面

继续按现有层级展示政策卡片。卡片分为三层：

1. 判断层：政策状态、机会等级、主要客户类型、主题。
2. 解读层：政策概要、企业机会、合规影响、建议动作。
3. 关联层：上位依据、配套细则、同主题政策。

关联政策使用站内可点击锚点；无法准确建立关系时不显示占位内容。

### 本周最新页面

保留新增、修订、截止和移出记录，并增加：

- 对客户与业务的影响；
- 建议本周动作；
- 若政策状态变化，说明对分类政策库的处理结果。

## 数据模型

每条政策在现有字段基础上增加：

- `id`：稳定、不可变的站内标识，用于政策关联和后续版本迁移。
- `validity`：`现行有效`、`滚动事项`、`待核实`、`已截止`、`已废止`或`被替代`。
- `opportunityLevel`：`高`、`中`、`观察`。
- `judgement`：一句话说明该政策属于利好、合规约束或持续观察事项。
- `customerTypes`：可能涉及的客户类型，控制在 2—4 个。
- `scenarios`：可能落地的业务场景，控制在 1—3 个。
- `relatedPolicies`：按 `上位依据`、`配套细则`、`同主题`记录关联政策 `id`。
- `analysisBasis`：说明该判断基于官方政策事实还是分析性推断。

### 事实与分析边界

- 发文机关、日期、有效期、申报期限、资助额度、适用条件等属于政策事实，必须以官方原文核验。
- 客户类型、机会等级、业务场景和建议动作属于分析判断，页面统一标注“业务研判”。
- 尚未精确回核的政策可以展示候选客户类型，但不得给出确定性的申报或合规结论。
- 不使用统一模板自动生成看似具体但未经核实的补贴金额、资质门槛或截止日期。

## 初始客户分类

首期使用稳定、可复用的客户标签：

- 大模型与智能体企业
- 云服务与算力运营商
- 芯片、服务器与数据中心企业
- 数据服务与数据运营机构
- 网络安全、数据治理与模型评测机构
- 央国企与大型企业数字化部门
- 制造、医疗、教育、金融、交通、文旅等行业客户
- AI 创业公司与 OPC
- 园区、科研机构和高校

标签按政策实际内容选取，不要求每项政策覆盖所有客户类型。

## 政策关系规则

- `上位依据`：本政策直接落实或承接的法律、规划、行动方案。
- `配套细则`：与本政策配套的实施指南、申报通知、名单、兑现办法或批次公告。
- `同主题`：不存在直接上下位关系，但在 AI、大模型、算力或数据主题上需要合并研判的政策。

关系必须能够说明业务价值。仅因标题出现相同关键词，不自动建立关系。

## 视觉与交互

沿用现有墨绿、纸张色和信号橙设计，保持政策简报的稳重感。新增元素采用：

- 机会等级：以“高 / 中 / 观察”的文字标签表达，不仅依赖颜色。
- 客户标签：紧凑的浅色标签组，可快速扫读。
- 政策关系：使用横向关系条，明确标出关系类型和关联政策标题。
- 卡片信息密度：默认完整展示判断与四项解读；关联政策放在卡片底部，避免干扰主要结论。

移动端改为单列，客户标签允许换行，关联政策保持可触控。

## 数据流与每周更新

1. 从官方来源核验新增、修订、截止、废止或替代事项。
2. 更新政策事实字段和生命周期。
3. 复核业务研判字段；新增政策补充客户类型、场景、机会等级和建议动作。
4. 建立或调整政策关系；配套通知与原政策互相引用。
5. 自动刷新首页统计、机会看板和合规提醒。
6. 在本周最新页记录政策库增删改结果。

失效政策不物理删除：从现行政策视图移出，并保留在历史数据中，记录失效或替代依据。

## 异常与空状态

- 没有可核验关联政策：隐藏关联区，不显示“暂无数据”。
- 客户类型属于初步判断：显示“业务研判”标识。
- 政策待回核：机会等级只能是“观察”，并保留醒目提示。
- 没有本周重大变化：首页和本周页明确说明扫描范围及“无已核验重大变化”。

## 测试与验收

- 36 项基线政策均有稳定 `id`，且 `id` 唯一。
- 每项政策均有生命周期、机会等级、客户类型和一句话判断。
- 待回核政策的机会等级必须为“观察”。
- 关联政策引用的 `id` 必须真实存在，且不得关联自身。
- 首页呈现本期判断及机会与风险看板。
- 三个分类页均显示机会等级和客户类型；至少重点政策显示关联政策。
- 事实字段与业务研判在界面上有明确区分。
- 国家、北京市级和区级导航及现有本周页面保持可访问。
- 桌面和移动端布局可读，键盘焦点可见。
- 构建及页面渲染测试全部通过后方可发布。

## 本期不做

- 不建设客户名称或销售线索数据库。
- 不自动推断具体企业一定符合申报条件。
- 不新增用户登录、订阅或后台编辑系统。
- 不为 36 项政策分别建立独立详情页。
- 不改变每周一 09:00 的更新约定。
