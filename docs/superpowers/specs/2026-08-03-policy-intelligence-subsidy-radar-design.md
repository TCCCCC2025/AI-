# 补贴申报雷达精准分析升级设计

## 目标

把补贴申报雷达从“政策清单”升级为领导可判断、客户经理可行动的政策情报入口。第一版以现有已核验政策为事实层；新闻、公众号和其他非正式渠道只作为线索，不直接作为政策事实。所有趋势、预警和客户建议都显示为基于事实的业务研判。

本轮先更新 ChatGPT Sites 主线，发布后等待用户确认，不自动同步 GitHub。同步维护一个可复用的“来源库”，把扫描过的网址沉淀下来，减少后续重复检索。

## 使用场景与成功标准

### 领导阅读

- 30 秒内看到当前开放窗口、支持机制、区域覆盖和本周最重要的变化。
- 能沿着一项补贴从上位政策看到实施细则、申报通知和实际入口。
- 能区分已核验事实与分析判断，避免把推测当作政策承诺。

### 客户经理会客

- 按客户类型快速筛出 Token、算力、数据、场景和 OPC 等匹配方向。
- 看到资格缺口、材料准备清单、建议联系部门和下一步动作。
- 能识别尚未开放但值得提前准备的政策窗口。

### 数据质量

- 每条正式补贴记录必须有可追溯来源、核验日期、状态和申报入口（若已公开）。
- “待持续扫描”不再作为单一状态，改为可解释的区域扫描状态。
- 事实、研判、线索三者在数据结构和页面文案上分离。

## 方案选择

### 方案 A：独立分析页

优点是信息分区清楚；缺点是领导和客户经理需要在两个入口来回切换，补贴事实与研判容易脱节。

### 方案 B：在补贴雷达内分层（采用）

保留 `/subsidies` 作为统一入口，在现有申报列表上方增加政策依据链、趋势与预警、客户准备度三个模块。使用一套结构化数据支撑四类视图，后续可复用到首页、领导页和客户经理页。此方案改动集中、验证边界清晰，也最符合现场使用。

### 方案 C：全站分析引擎重构

长期扩展性最好，但会同时影响首页、领导页、客户经理页和多条导航，第一版难以快速核验，不采用。

## 页面设计

### 1. 顶部总览

保留现有指标，并补充：

- 当前可申报窗口数；
- 政策有效但等待批次数；
- 需要提前准备的窗口数；
- 已核验区域数 / 已扫描区域数。

指标旁显示“截至日期”和事实口径。没有已核验重大变化时，明确显示“本周无已核验重大变化”。

### 2. 政策依据链

每项重点补贴显示四级链路：

`上位战略或政策依据 → 北京/区级实施政策 → 当期指南或申报通知 → 申报入口`

每个节点包含标题、发布机构、日期、来源链接和来源类型。缺少某一级时显示“尚未检出公开文件”，不补写推测内容。

### 3. 支持机制与状态

统一展示以下字段：

- 支持方向：Token、算力、数据、场景、模型、OPC 等；
- 兑现机制：现金奖励、事后补贴、电子券、即时抵扣、免申即享、资源对接；
- 受益对象：模型/应用企业、算力服务商、数据服务商、场景单位、平台/园区；
- 状态：当前可申报、政策有效但等批次、已截止、线索待核验；
- 适用范围：市级、区级、特定园区或特定注册/落地条件。

“已截止”记录仍保留在历史区，但不计入当前可申报金额和窗口统计。

### 4. 趋势与预警

趋势卡片必须拆成三栏：

- **已核验事实**：直接来自正式来源的可复述信息；
- **业务研判**：基于多项事实的归纳，不表述为政策承诺；
- **下一信号**：后续扫描时要验证的文件、入口或时间节点。

预警条目包含：触发信号、可能的政策动作、预计准备周期、建议动作、置信度（高/中/观察）。重点关注 Token/算力券、数据集与场景揭榜、OPC/智能体生态、即时平台兑换和区级配套批次。

### 5. 客户准备度

按客户类型提供轻量 checklist，不计算不可解释的总分。每项为“已具备 / 待补齐 / 不适用”，并给出证据要求：

- 大模型/智能体企业：主体资格、模型备案/登记、产品说明、算力账单、场景合同或意向；
- 算力与云服务商：资源证明、服务目录、计费口径、交付与安全能力；
- 数据服务商：数据权属、授权链、数据集说明、合规与安全材料；
- 场景单位/央国企：场景需求、预算与采购路径、数据提供边界、验收指标；
- OPC/初创企业：主体或园区身份、产品原型、知识产权、融资/路演和申请窗口。

每种客户类型提供“现在做什么、等什么信号、谁负责联系”的三步行动卡。

### 6. 区域扫描状态

区域卡片改用以下枚举：

- `已核验政策`：已找到并核对正式政策或申报通知；
- `已扫描未检出正式记录`：已按既定渠道扫描，当前没有可作为正式结论的记录；
- `存在待核验线索`：发现新闻、公众号、园区或平台线索，但尚未形成正式来源闭环；
- `待持续扫描`：本轮尚未完成等深度扫描。

同时记录最近扫描日期、已检查渠道、线索数量和下一次复核日期。页面提示说明：未检出不等于当地没有政策。

### 7. 来源库

新增 `/sources` 入口，作为所有扫描网址的目录，不把网址只埋在政策卡片里。每条来源至少展示：

- 标题或页面名称、网址、发布机构/平台；
- 来源类型：正式政策、申报入口、官方转载、园区/平台动态、新闻/公众号线索；
- 对应层级和区域：国家、北京市级、区级或其他；
- 首次发现日期、最近核验日期、核验结果；
- 关联政策/补贴 ID、备注和下一次复核日期。

来源库支持按关键词、区域、来源类型和核验结果筛选，并提供“只看待核验线索”视图。正式来源与线索来源使用不同视觉标签；线索来源不能被统计为正式政策依据。后续周更先复用来源库中的高价值入口，再补充新增网址。

## 数据模型

在 Sites 主线新增可复用的结构化模块（建议为 `app/subsidy-intelligence-data.ts`），不把分析判断散落在 JSX 中。

### 正式政策记录扩展

- `id`, `title`, `region`, `supportDirections[]`, `mechanism`, `beneficiaries[]`；
- `status`, `applicationWindow`, `amount`, `eligibility`, `applicationUrl`；
- `basisPolicyIds[]`, `sources[]`, `verifiedAt`, `sourceGrade`；
- `summary`, `businessImpact`, `complianceImpact`, `action`。

`sourceGrade` 至少区分 `official`、`official_repost`、`lead_only`；只有前两类可以进入正式政策统计。

### 研判记录

- `fact`: 已核验事实文本；
- `judgement`: 业务研判文本；
- `nextSignal`: 下一次扫描验证项；
- `confidence`: 高 / 中 / 观察；
- `horizon`: 近期 / 1—3 个月 / 中期；
- `relatedPolicyIds[]`。

### 预警与准备度

- 预警：`trigger`, `likelyAction`, `leadTime`, `recommendedAction`, `confidence`；
- 准备清单：`customerType`, `items[]`, `evidence`, `owner`, `state`。

### 区域扫描

- `district`, `scanStatus`, `lastScanned`, `channelsChecked[]`, `leadCount`, `nextReview`。

### 来源库记录

- `url`, `title`, `publisher`, `sourceType`, `level`, `region`；
- `firstSeen`, `lastVerified`, `verificationStatus`, `relatedPolicyIds[]`；
- `notes`, `nextReview`。

## 数据流与核验规则

1. 先收集正式来源和可追溯入口；非正式来源仅进入线索队列。
2. 逐条核对发布时间、适用期限、申报窗口、支持对象、金额和兑现方式。
3. 只有完成来源闭环的记录进入正式政策统计；未闭环记录显示为线索或待扫描。
4. 将事实写入政策记录，再由事实生成研判、预警和客户动作；研判字段不能反向改变政策状态。
5. 对过期、截止、废止或被替代事项，从当前窗口移出，保留历史及调整依据。
6. 每次扫描无论是否形成政策记录，都将访问过且有复用价值的网址登记到来源库；无法访问或仅为临时跳转的地址记录原因，不作为正式依据。

## 测试与验收

- 数据测试：正式记录字段完整；来源等级与状态组合合法；事实和研判字段均非空且分离。
- 区域测试：四种扫描状态都能正确渲染，且“已扫描未检出”不计入正式政策数。
- 页面测试：总览指标、依据链、趋势/预警、客户准备度和区域状态出现在静态 HTML；入口链接可访问。
- 来源库测试：所有种子来源可检索；正式来源与线索来源标签不同；关联政策和核验状态可显示。
- 构建测试：`npm run lint`、`npm test`、`npm run build` 全部通过。
- 发布验收：仅发布到 ChatGPT Sites；检查首页、`/subsidies` 和移动端基本可读性；不推送 GitHub。

## 非目标

- 本轮不将未经核验的新闻或公众号内容发布为政策事实。
- 本轮不新增登录、用户画像、在线申报或数据库写入。
- 本轮来源库使用版本化静态数据，不承诺自动抓取或永久保证外部网址有效。
- 本轮不自动同步 GitHub；用户确认后才执行 GitHub 同步。
