# 补贴申报雷达周更手册

补贴雷达的正式结论维护在 `app/subsidy-data.ts`。它服务领导和客户经理，但不代替企业申报；每条金额、条件、期限和入口都必须能回到官方政策、通知、附件或官方平台。

## 每周更新顺序

1. 扫描北京市级、16 区和北京经开区，主题包括算力券、模型券/Token 券、数据券、备案、场景、人才/OPC。
2. 以新闻、公众号、园区文章作为线索；找到线索后回到发文机关、政府门户、政策兑现专区或官方附件核验。
3. 逐条更新 `status`、`deadline`、`applicationWindow`、`amount`、`eligibility`、`portal`、`lastVerified` 和 `verificationNote`。
4. 先在 `app/policy-data.ts` 的 `weeklyChanges` 中记录本周的“新增、修订、截止、移出”，再同步补贴记录。已截止事项保留在政策库，但不得出现在“当前窗口”。
5. 没有官方依据的新闻/公众号线索只能放入核验队列，不得写成“当前可申报”或确定补贴金额。
6. 运行 `npm run lint`、`npm test` 和 GitHub 同步 dry-run。

## 状态判断

- `open`：官方通知明确在申报期内，或官方平台明确持续开放。
- `closing_soon`：距离官方截止日不超过 30 天，且通知没有被替代或暂停。
- `rolling`：政策有效，按批次、额度或平台余额滚动开放。
- `effective_no_round`：政策有效，但本周没有找到正在开放的申报批次。
- `closed`：本轮申报已结束；保留金额和条件作为下一轮准备依据。
- `pending_verification`：只有二手线索或官方动态，尚未取得足够的正式申报依据。

## 证据等级

- `A`：发文机关政策原文、申报通知或官方附件，金额/条件/入口可以定位。
- `B`：政府门户转载或官方政策解读，可以交叉核验关键事实。
- `C`：区级官方工作动态或官方媒体，只支持平台上线、方向和服务事实。
- `lead`：新闻、公众号或行业媒体线索，只能作为核验任务。

## 业务复核清单

- 客户注册地、税务地、统计地和项目落地地是否满足属地要求。
- 客户是模型供给方、算力使用方、数据采购方、场景建设方，还是 OPC/初创企业。
- 金额是现金奖励、事后补贴、电子券抵扣还是平台即时折扣，是否可以叠加。
- 是否已有同一项目获得市级、区级或其他专项资金，是否触发查重或从优不重复。
- 是否保留合同、发票、付款、算力计量日志、Token 调用量、备案、数据交易和应用成效证明。
